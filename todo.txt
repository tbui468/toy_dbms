    Cache page replacement algorithms are a fun/easy place to start our database system implementation.  
    Grabbing pages from disk is very expensive (in terms of time), so storing currently used page data in memory is ideal.  

    The buffer pool manager's job is to act as a cache for the DBMS.  

    Since the amount of memory is small compared to disk space, we need a way of determining which pages to keep in memory and which pages to put back into disk.  
    
    Page eviction algorithms often use recency or frequncy to determine which page to evict.  
    The simpliest algorithm is to evict the the least recently used page (LRU).  

    Many more advanced algorithms are variants of LRU or/and least-frequently-used (LFU).  
    For example the clock-sweep algorithm is an approximation of LRU, and the ARC algorithm uses both recency and frequency to determine which page to evict.  

    We will keep things simple in order to get the entire system up and running as quick as possible, so we'll stick to the bog-standard LRU algorithm.

    The LRU replacer will have a pool of frames that is can track.  A frame will be in one of three states: free, fix or unfixed.  Fixing a frame will prevent it from being replaced, ie a worker is using the in-memory page.  An unfixed frame still tracks an in-memory page, but it unused and can be evicted.  A free frame is unused and can be fixed if a page from disk needs to be brought in and used.  
    If a new page needs to be fixed but there are no free frames remaining, an unfixed frame will evict its page data, and the new page loaded into that frame.  The LRU algorithm will choose to evict the frame that has been unfixed for the longest time.  

    Our replacer implemenation will keep allocating frames if fix will called.  The responsibilty of tracking free and fixed frames will be handled by the buffer pool manager (which will be discussed in a later writeup).  The replacer will only determine which unfixed frame to evict.

    The replacer starts with a pool of free frames.  Let's say we only have enough memory to store 5 pages in memory, ie we have 5 free frames.

    [image]
    A worker needs three pages from disk.  Three free frames (with ids 0, 1 and 2) are fixed and the page data read from disk so that the worker can do its thing.  After some time the worker is done with frame 1 and 2, and so frame 1 is unfixed followed by frame 2.

    The unfixed frames are appended to a a list.  The oldest unfixed (least-recently-used) frame will always be at the front of the list, and the most recently unfixed at the end.

    Now a different worker also needs 3 frames to load in 3 different pages.  Frames 3 and 4 can be taken from the free frame pool and fixed, but that leaves us short a frame.  But the unfixed frames are unused, so they can be evicted to make space for different page data.  We will evict the frame at the front of the list, frame 1, and let this worker use it (along with writing/reading page data from disk as necessary).
